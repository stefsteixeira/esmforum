# Planejamento de Pair Programming

## Aplicação da prática

Embora este projeto esteja sendo desenvolvido individualmente, a prática de Pair Programming poderia ser aplicada durante a implementação das novas funcionalidades propostas para o ESM Forum.

No Pair Programming, duas pessoas trabalham em conjunto na mesma tarefa. Uma delas assume o papel de 'Driver', sendo responsável por escrever o código, enquanto a outra atua como 'Navigator', acompanhando o desenvolvimento, revisando o que está sendo feito e sugerindo melhorias.

## Estratégia de trabalho

Para o desenvolvimento do ESM Forum, a dupla poderia trabalhar inicialmente na análise da funcionalidade que será implementada e definir uma solução antes de começar a alteração do código.

Durante a implementação, uma pessoa atuaria como Driver e ficaria responsável pela escrita do código. A outra pessoa seria o Navigator, acompanhando a implementação e verificando possíveis erros, melhorias e alternativas.

Os papéis seriam alternados periodicamente, por exemplo, a cada 30 minutos ou após a conclusão de uma pequena etapa da funcionalidade. Dessa forma, os dois integrantes participariam diretamente tanto da implementação quanto da revisão do código.

Um possível fluxo seria:

1. Escolher uma funcionalidade do quadro Kanban.
2. Analisar os requisitos da funcionalidade.
3. Definir quais partes do sistema precisarão ser modificadas.
4. Definir quem começa como Driver e quem começa como Navigator.
5. Implementar uma pequena parte da funcionalidade.
6. Executar e testar o código.
7. Trocar os papéis.
8. Continuar o desenvolvimento até a conclusão da funcionalidade.
9. Realizar uma revisão final em conjunto.

## Ferramentas

Para permitir o trabalho colaborativo, poderiam ser utilizadas ferramentas como:

- Visual Studio Code para desenvolvimento do código;
- Visual Studio Live Share para edição e acompanhamento do código em tempo real;
- Discord ou Google Meet para comunicação durante a sessão;
- GitHub para controle de versão e acompanhamento das alterações;
- GitHub Projects para acompanhar o andamento das tarefas no quadro Kanban.

## Benefícios para o projeto

A utilização de Pair Programming poderia contribuir para a identificação mais rápida de erros e para a melhoria da qualidade do código. Como o código é acompanhado por duas pessoas durante sua criação, ocorre uma revisão contínua durante o próprio desenvolvimento.

Além disso, a troca entre Driver e Navigator permite que ambos compreendam as decisões tomadas e as diferentes partes do sistema. Isso também facilita a discussão de soluções antes que alterações desnecessariamente complexas sejam adicionadas ao projeto.

No ESM Forum, essa prática poderia ser especialmente útil durante a implementação das novas funcionalidades, pois alterações no backend e no frontend poderiam ser analisadas em conjunto antes de serem incorporadas ao sistema.

## Conclusão

Mesmo sendo um projeto desenvolvido individualmente, o Pair Programming poderia ser aplicado caso o desenvolvimento fosse realizado em dupla. A estratégia de alternância entre Driver e Navigator, associada ao uso de ferramentas de colaboração, permitiria manter uma revisão constante do código e compartilhar as decisões tomadas durante a implementação.
